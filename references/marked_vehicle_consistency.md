# 指定车辆或路面参照物的时间轴复核与运动状态分析

本参考文件用于用户已标注车辆或路面参照物后，按以下顺序分析：

1. 提取视频元数据和帧图片。
2. 利用视频画面复核时间轴/帧率。
3. 根据速度矢量分析车辆或参照物运动状态。

车辆/参照物画面运动状态分析与时间轴一致性判断同等重要。当前文件重点给出第二步和第三步的判断规则。

## 共同数据要求

- 用户已指定车辆或路面参照物时，必须使用其标注、ROI或任务语义限定的目标，不得自行替换。用户未指定目标时，按 `motion_continuity_sop.md` 的最少车辆完整覆盖规则选择并记录候选目标。
- ROI 坐标使用原始视频帧坐标。标注图尺寸不同于原始帧时，先按比例换算并写明换算过程。
- 统一使用 `rel_pts_time = pts_time - first_pts_time`。
- 相邻帧时间差使用 `delta_pts_time = rel_pts_time_i - rel_pts_time_{i-1}`；不要用固定帧率替代真实逐帧 PTS 差分，除非报告明确说明该固定值来自逐帧核验。
- 原始逐帧测量值必须保留。不要用平滑、插值、趋势线或锚点估计替代原始相邻帧差分。
- `pixel_speed` 是图像平面量，不是实际物理车速。第二步用它复核画面有效帧率；第三步用它描述车辆/参照物画面运动状态。

基础计算：

- `dx = x_i - x_{i-1}`
- `dy = y_i - y_{i-1}`
- `pixel_displacement = sqrt(dx^2 + dy^2)`
- `pixel_speed = pixel_displacement / delta_pts_time`

## 第二步：画面复核时间轴/帧率

目标：判断 PTS 时间轴、标称帧率和画面有效帧率是否一致。`pts_time` 线性递增只说明编码层时间戳连续，不能单独证明画面内容按相同节奏更新。

复核证据：

- 画面 OSD 时间跳 1 秒实际跨越多少帧。
- 帧号连续性、`delta_pts_time`、`duration_time`、`pict_type`。
- 帧哈希是否重复或近重复。
- ROI 相邻帧差分是否持续存在。
- 速度矢量 cadence，例如近零位移帧、高速度帧、方向突变是否有周期性。
- GOP/packet 是否异常。
- 选定区间或帧级 `intra_pct` 是否异常升高。

异常候选：

- `pixel_speed` 接近 0，但目标应持续运动：疑似冻结帧、重复帧、双倍帧、特征点丢失或 ROI 跟踪失败。
- `pixel_speed` 约为前后稳定值 2 倍或差分突增：疑似 PTS 间隔异常、跳帧、补帧、ROI 漂移或画面突变。
- `pixel_speed` 出现 `1,4,1,4,1,3`、`4,4,3` 等周期性 cadence：优先作为画面有效帧率与 PTS/标称帧率不一致的候选，结合 OSD 跳秒帧数和帧哈希复核。
- 方向角或 `dx/dy` 与前后帧明显冲突：疑似遮挡、目标切换、模板漂移或视频流画面异常。

判断规则：

- 若画面 OSD 跳秒帧数、帧哈希或速度矢量 cadence 与 `pts_time`/标称帧率不一致，不要直接用 PTS 推定画面真实帧率。
- 若画面位移连续、ROI 差分连续、`intra_pct` 无异常，但 `delta_pts_time` 存在双倍间隔或跳变，偏向 PTS/时间轴问题。
- 若 `delta_pts_time` 正常，但画面差分、帧哈希或速度矢量显示重复/停顿，偏向画面有效帧率、转码补帧、重复帧或冻结帧问题。
- 若像素速度局部升高，但差分图显示车辆轮廓、车灯、轮胎、路面反光等连续变化，优先解释为透视关系、车辆姿态变化、灯光/反光或轮廓分割波动，不直接认定时间轴异常。
- 第二步必须给出后续时间基准：继续使用 `rel_pts_time`，或改用基于画面时间和画面运动状态校准后的有效时间基准。

## intra 宏块占比

如执行环境能够通过 FFmpeg `-debug mb_type` 或等效方法统计，`intra_pct` 表示对应帧的全帧 intra 宏块占比。

- `intra_pct` 只能作为辅助指标，不能单独证明视频剪辑或时间轴错误。
- 除非另行裁剪视频或扩展脚本按 ROI 宏块范围统计，不得把全帧 `intra_pct` 表述为 ROI 内 intra 宏块占比。
- 若 `delta_pts_time` 正常、ROI 像素速度异常且 `intra_pct` 同步升高，优先复核画面突变、编码刷新、遮挡或 ROI 跟踪问题。

## 第三步：车辆或参照物运动状态

第三步必须在第二步确认或校准时间基准后进行。车辆或参照物运动状态分析与时间轴一致性判断同等重要，但问题不同：第三步描述目标在画面中的运动方向、连续性和速度矢量变化是否可解释。

分析要点：

- 车辆 ROI 应随车或随车身局部参照物逐帧确认；路面 ROI 应固定在指定路面参照物附近。
- 优先使用多个稳定参照物：前/后轮中心、车身边缘、车牌、车灯、车窗角点、轮廓中心、路面标线交点或导向箭头边缘。
- 速度矢量必须来自同一特征点、同一车身局部或同一路面参照物从上一帧到当前帧的实际位移。
- 不要把每帧重新检测出的候选点直接当作同一追踪点；若使用新候选点，只能作为辅助判断。
- 同一车辆上的多个稳定特征点应表现出可解释的整体平移、缩放或旋转关系。
- 前、后轮中心点因透视关系可能有不同像素速度，但车辆作为刚体，其画面运动应具有可解释的连续性。
- 车辆远离摄像头时，像素速度和像素轴距通常可能减小；车辆接近摄像头时则相反。该规则是透视解释，不是硬性车速计算。
- 若透视关系、刚体运动和轨迹连续性不能解释某帧突变，标为需复核，并列出帧号、时间、像素速度、ROI 状态和编码层复核结果。

## 可视化要求

- 输出逐帧速度矢量图：标明 ROI、特征点编号、箭头、`dx/dy`、`delta_pts_time`、`pixel_speed`。第一帧标为基准帧。
- 输出速度矢量时间曲线：横轴为 `to_rel_pts_time` 或校准后的画面有效时间；纵轴至少包含 `dx/dt`、`dy/dt`、`pixel_speed`，标注单位 `px/s`、帧号和异常候选点。
- 热力图、轨迹叠加图和差分图只用于辅助定位运动带、轮廓扩散范围和差分强度集中区，不能单独作为结论。

## 结论模板

1. 第一步元数据和帧图提取：帧号范围、`rel_pts_time`、`delta_pts_time`、GOP/packet/帧哈希状态。
2. 第二步时间轴/帧率复核：ROI 坐标、速度矢量 cadence、OSD 跳秒帧数、重复/近重复帧、`intra_pct` 和 PTS/标称帧率对应关系。
3. 第二步结论：PTS 时间轴、标称帧率和画面有效帧率是否一致；第三步采用 PTS 还是校准后的画面有效时间基准。
4. 第三步车辆/参照物运动状态：运动方向、连续性、透视关系、刚体运动和异常候选。
5. 边界说明：像素速度不是实际物理车速；车辆运动状态分析必须考虑车辆自身物理运动和透视关系共同造成的像素速度变化。
