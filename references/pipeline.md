# 视频测速前置审查流程

## 目录

1. 明确任务
2. 固定证据
3. 编码时间轴
4. 画面内容与OSD
5. 目标运动
6. 综合推断
7. 最终复核

## 1. 明确任务

- 确定视频、时间/帧号区间、预期结论和用户指定目标。
- 明确只审查后续测速所需的时间条件，不计算实际车速。
- 缺少OSD、ROI或来源信息时记录限制，不阻断其他可验证维度。

## 2. 固定证据

- 记录路径、文件名、字节数、修改时间和SHA-256。
- 记录FFmpeg、FFprobe、OpenCV/OCR等工具和版本。
- 保存命令、参数、完整元数据和解码错误输出。
- 直接解码原文件；导出PNG等无损帧图只作为观察材料。

进入下一阶段的条件：输入文件可读，原始证据和运行环境可追溯。无法解码时停止画面分析并报告。

## 3. 编码时间轴

逐帧保存：显示序号、PTS、DTS、best-effort timestamp、相对PTS、相邻PTS差、duration、帧型、关键帧和packet位置/大小（可取得时）。

检查：

- 非递增、重复或异常间隔；
- GOP和帧型变化；
- packet不连续或解码错误；
- 声明帧率、平均帧率和实际PTS节律是否一致。

PTS均匀只说明成品编码时间戳规律，不证明画面内容等间隔更新。

## 4. 画面内容与OSD

- 屏蔽OSD后检查完全重复、近似重复、冻结和全局突变。
- 逐帧识别OSD秒值并保存原图、识别值和人工校对状态。
- 定位OSD跳秒到达帧，统计相邻跳秒帧之间的成品帧间隔。
- 首尾不足一个完整OSD秒时标为边界，不用于帧率模型判断。

哈希不同不必然代表有实质运动更新；OSD连续也不能单独证明内容采样连续。

## 5. 目标运动

先读取 `method-selection.md` 选择方法。需要逐相邻帧车辆分析时遵循 `motion_continuity_sop.md`。

- 列出全部待评价帧对。
- 选择能完整覆盖的最少车辆。
- 车辆片段按实际质量范围展开，交接处尽量保留2至3个重叠帧对。
- 保存每个目标的原始测量、局部基线、格式化倍率和质量指标。
- 无合格目标的帧对标记为不可评价。

## 6. 综合推断

先列观察事实，再比较至少以下解释：

- 编码时间间隔异常；
- 周期性删除或重复画面内容；
- 跟踪漂移、特征不足或目标切换；
- 遮挡、反光、编码刷新或场景突变；
- 车辆真实加速、制动、转向或碰撞；
- 透视尺度变化。

只有多层证据共同支持时，才能提升结论强度。原因不唯一时保留竞争假设。

## 7. 最终复核

逐项记录“通过 / 不通过 / 无法验证”和证据位置：

- 原始文件与运行环境；
- PTS/DTS/GOP/packet；
- 重复、冻结和内容更新；
- OSD跳秒与边界秒；
- 目标身份、覆盖率、重叠交接和质量；
- 原始测量、倍率、候选和推定计数；
- 替代假设和结论边界；
- CSV、图表、证据图片和报告之间的一致性。
- 报告、图中阈值线和配置文件使用同一候选阈值。
- 原始欧氏位移、投影位移、代表车辆倍率和跨车共识倍率字段可代数复核且来源明确。
- 成品OSD秒间帧间隔数与倍率推定原始帧间隔数没有混名；跳秒归属和边界秒口径一致。
- 人工复核精简表只保留必要字段；`OSD秒间帧数` 按共识倍率分级在秒内逐行累计，`异常标记` 与候选阈值一致。
- 交付目录按审阅顺序组织为报告、数据、图表、证据和复现资料，并提供索引；根目录不堆放明细产物。

禁止使用无证据的“整体正常”“基本可靠”等笼统表述。
