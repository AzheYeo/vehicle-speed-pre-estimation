# 视频帧与基础数据提取

## 任务边界

根据用户提供的视频文件地址和播放器时间区间，固定文件摘要，提取容器与视频流信息，导出指定画面的原始解码帧及一张逐帧CSV。

只记录直接读取、解码或从画面识别的数据。不要分析车辆运动连续性，不要根据PTS、帧型或单项指标认定跳帧、删帧、补帧或冻结。

## 输入

至少取得视频文件地址和播放器时间区间。把用户给出的时间解释为播放器进度条时间，允许使用秒数或 `HH:MM:SS.mmm`。缺少时间区间时再询问，不要求用户提供专业参数。

## 时间定义与定位

1. 按全视频显示顺序解码，确定首个实际可显示帧。
2. 使用该帧的 `PTS时间_s` 作为播放器时间漂移基准：

```text
播放器时间_s = 当前帧PTS时间_s - 全视频首个可显示帧PTS时间_s
```

3. 不要用“时间×标称帧率”推算帧序号。
4. PTS缺失时才使用 `best_effort_timestamp_time_s` 定位，并在数据状态中注明。
5. 如果按播放器时间导出的画面与用户指定目标不一致，参考画面OSD时间重新定位；保留原始PTS，不用OSD值覆盖编码时间。
6. 为确定OSD秒间帧序号，可在目标区间前后额外解码缓冲帧。缓冲帧只用于定位OSD跳秒边界，正式帧图仍按目标区间交付。
7. `OSD秒间帧序号` 从同一显示OSD秒出现的第一帧开始计数，OSD秒变化时重新从1计数。无法找到该秒起点时标记边界不完整，不要从提取区间第一帧武断编号。

## 帧序号与图片

- 以全视频首个实际可显示解码帧为第1帧，按显示顺序建立全局 `帧序号`。
- 截取局部区间时保留全局序号，不从1重新编号。
- 帧图使用PNG等无损格式。
- 按本次最大帧序号的动态位宽命名为 `frame_n.png`，例如 `frame_007.png`、`frame_042.png`、`frame_105.png`。
- CSV中的 `帧序号`、`图片文件`和实际帧图必须一一对应。

## 输出

只生成一套便于人工复核的基础产物：

```text
info_<播放器起始时间>-<播放器结束时间>.txt
逐帧数据_<播放器起始时间>-<播放器结束时间>.csv
帧图片_<播放器起始时间>-<播放器结束时间>/
```

时间统一使用连续数字格式，例如整秒区间 `000120-000125`，带毫秒区间 `000120000-000125000`。不要把任务时间区间重复写进info正文。

完整读取 `references/output-schema.md`，按其中顺序生成info和CSV。只生成一张CSV，不再拆分元数据表、OSD表、帧型表或其他统计表。

第一阶段CSV预留第二阶段字段：

- `修正后OSD秒间帧序号` 先等于 `OSD秒间帧序号`；
- `运动异常备注` 留空；
- `推定帧间隔增量` 默认填1；
- 其余运动分析字段留空。

## 数据规则

- `PTS时间_s` 保留视频中的原始 `pts_time`。
- `相邻PTS差_s = 当前帧PTS时间_s - 上一显示帧PTS时间_s`；全视频首帧留空，不填0。
- 同时保留整数PTS和 `time_base`，不要只保存舍入后的秒值。
- `DTS` 缺失时保留空值或 `N/A`，不要伪造。
- `OSD时间` 固定为八位 `hh:mm:ss`，小时、分钟、秒均保留两位和前导零，例如 `08:03:09`；不输出OSD日期。
- 区分帧类型与关键帧：帧类型写I、P或B，关键帧单独记录。
- 所有时间小数保留足以由原始整数时间戳和 `time_base` 复算的精度。
- OCR原始结果、标准化结果和人工校对状态不得互相覆盖。
- 在 `info.txt` 中列出目标区间内全部可确认的OSD跳秒到达帧。到达帧指画面OSD秒值发生变化后的第一帧；同时写明前后OSD时间和该到达帧PTS。该记录只描述OSD变化，不作为跳帧结论。

## 完成检查

确认摘要信息适合直接复制；容器信息、视频流信息、OSD跳秒到达帧和复现信息完整；用户播放器区间映射到正确画面；帧序号来自全片实际显示顺序；逐帧字段与图片对应；CSV只有一张；本阶段没有写入运动异常结论。
